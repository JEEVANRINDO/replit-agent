# Build a **real** end-to-end encrypted (E2EE) web chat app (HTML/CSS/JS) using Firebase backend  
## Professional Roadmap → Module-by-Module → Verified → Final Integration

**Important overall rule:** Use **libsignal-protocol-typescript** exclusively for all E2EE functionality. No fallback libraries or fallback runnable code allowed. If `libsignal-protocol-typescript` cannot run in the target environment (missing WebCrypto, incompatible browser, etc.), the generator must not produce runnable app code — instead produce only the alternative architecture proposals (ideas-only) and an explicit environment-compatibility report explaining why the library cannot run.

## 1) Roadmap — Phases & Order (must follow)
1. Environment & prerequisites check  
   - Verify browser WebCrypto availability, required browser versions, bundler/runtime constraints.  
   - If incompatible, stop and produce architecture proposals only.

2. Project scaffolding  
   - package.json, bundler config, basic index.html, firebase-config.js (placeholder).

3. Authentication & Firestore basics  
   - Implement Firebase Auth (signup/signin) and simple Firestore read/write.  
   - Unit test: sign-up, sign-in, write/read one public document.

4. Crypto primitives & storage (Signal client setup)  
   - Implement key generation (identity, signed prekey, multiple one-time prekeys) and client-side persistent storage (IndexedDB).  
   - Unit test: generate keys → read back from IndexedDB → compute fingerprint.

5. Prekey bundle registration  
   - Upload only public key material to Firestore under `/users/{uid}/prekeys`.  
   - Unit test: confirm uploaded documents contain only public fields (no private key bytes).

6. Session establishment (pairwise)  
   - Implement SessionBuilder using recipient’s public bundle; create session state locally.  
   - Unit test: simulate Alice building session with Bob’s bundle and verify session exists locally.

7. Message encryption/decryption flow  
   - Sender: encrypt with SessionCipher and push ciphertext to `/chats/{chatId}/messages`.  
   - Recipient: listen, decrypt, display.  
   - Unit test: two browser sessions (or simulated instance) exchange a short message and both decrypt successfully.

8. UI & polish (minimal usable UI)  
   - Chat list, message view, key fingerprint display, "refresh prekeys" button.  
   - Acceptance test: manual UX checklist (login, register, create chat, exchange messages).

9. Firestore security rules & audit  
   - Provide `firestore.rules` that allow only authenticated public prekey writes and ciphertext reads by participants.  
   - Test: attempt unauthorized read/write should be blocked.

10. Build, docs, SECURITY.md, README, deploy instructions  
    - Include instructions for pasting Firebase config, build steps, how to verify E2EE.

11. Final integration & end-to-end QA  
    - Run full scenario with two fresh browser sessions, confirm all acceptance tests pass, and show Firestore entries containing only ciphertext.

## 2) Module Acceptance Criteria (for each module)
For each module produced, include a short "Acceptance Criteria" block that lists PASS conditions (what to verify) and FAIL conditions (what breaks). Example for Prekey registration:
- PASS: IndexedDB contains private keys; Firestore `/users/{uid}/prekeys` contains only public keys; no private material uploaded.  
- FAIL: Any stored Firestore document includes a field resembling a private key or session secret.

Each source file must include inline comments pointing to relevant acceptance criteria and which test verifies them.
